# استانداردهای کیفیت و شروط پذیرش

این موارد هدف و قرارداد تحویل‌اند؛ هنوز اندازه‌گیری یا تأیید اجرایی نشده‌اند. نتیجه هر بررسی با محیط، مسیر، زبان و محدودیت آن ثبت شود.

## Performance

- هدف داده میدانی در صدک ۷۵، جدا برای موبایل و دسکتاپ: LCP حداکثر ۲٫۵ ثانیه، INP حداکثر ۲۰۰ میلی‌ثانیه و CLS حداکثر ۰٫۱.
- پیش از وجود ترافیک، تست آزمایشگاهی روی build تولید با تنظیم ثابت موبایل و شبکه ثبت شود؛ نمره آزمایشگاهی جای داده میدانی را نمی‌گیرد.
- هدف داخلی Lighthouse روی خانه، فهرست و محصول: Performance حداقل ۹۰ و دسته‌های Accessibility، SEO و Best Practices حداقل ۹۵؛ نمره به‌تنهایی اثبات کیفیت نیست. هر استثنا مستند و رفع یا پذیرفته شود.
- تصویر responsive با ابعاد مشخص و فرمت مناسب؛ تصویر اصلی بالای صفحه به‌موقع بارگیری و تصاویر پایین صفحه lazy شوند. preload بدون نیاز انجام نشود.
- فونت با مجوز روشن، میزبانی مناسب، وزن محدود و fallback نزدیک؛ از جابه‌جایی متن جلوگیری شود.
- JavaScript کلاینت حداقل؛ ابزار تحلیل، چت AI و اجزای سنگین در زمان نیاز بارگیری شوند. تغییر اندازه bundle در PRهای مؤثر بررسی شود.
- queryهای دیتابیس، indexها، N+1 و صفحه‌بندی با داده نماینده بررسی شوند؛ بودجه latency متناسب با میزبانی و بار واقعی تعیین شود.
- glass و motion روی موبایل ضعیف بررسی شوند؛ کاهش جلوه برای reduced-motion و امکان fallback بدون backdrop-filter.

## SEO

- محتوای اصلی خانه، دسته و محصول در HTML سرور قابل خواندن باشد.
- title و description محلی، canonical مستقل هر ترجمه، hreflang متقابل و x-default مطابق سیاست زبان، sitemap و robots صحیح.
- Product/Offer/Breadcrumb و Organization فقط با داده واقعی و مطابق صفحه؛ rating، تخفیف یا موجودی جعلی در structured data نباشد.
- آدرس پایدار، redirect برای تغییر slug، 404 واقعی برای منبع ناموجود و سیاست روشن برای محصول موقتاً ناموجود یا حذف‌شده.
- ترکیب‌های فیلتر و جست‌وجوی داخلی باعث انفجار صفحات قابل ایندکس نشوند؛ canonical/noindex طبق نوع صفحه تعیین شود.
- حساب، سبد، checkout، پنل و staging قابل ایندکس نباشند. robots کنترل دسترسی نیست؛ staging و پنل به محافظت واقعی نیاز دارند.
- metadata شبکه اجتماعی و تصاویر اشتراک‌گذاری از هویت مرکزی؛ alt متناسب با محتوا و زبان.
- کش، قیمت و structured data با محتوای قابل مشاهده هماهنگ باشند؛ تضمین رتبه جست‌وجو داده نمی‌شود.

## Accessibility

هدف WCAG 2.2 سطح AA در مسیرهای اصلی است؛ آزمون خودکار به‌تنهایی اثبات انطباق نیست.

- HTML معنایی، landmark، عنوان‌های مرتب، skip link، نام قابل دسترس کنترل‌ها و label واقعی فرم.
- کنتراست متن معمول حداقل ۴٫۵:۱، متن بزرگ ۳:۱ و اجزای غیرمتنی لازم ۳:۱؛ شفافیت glass در بدترین پس‌زمینه ارزیابی شود.
- تمام کارها با صفحه‌کلید؛ focus واضح، بدون گیر افتادن، و مدیریت focus در dialog و navigation.
- حداقل اندازه هدف لمسی مطابق معیار AA و هدف طراحی ۴۴×۴۴ پیکسل برای کنترل‌های اصلی.
- reflow در عرض ۳۲۰ CSS pixel و بزرگ‌نمایی؛ جدول مشخصات و محتوای ذاتاً دوبعدی مدیریت مناسب داشته باشند.
- وضعیت سبد، خطا و نتیجه عملیات برای screen reader اعلام شوند؛ live region بیش‌ازحد استفاده نشود.
- رنگ تنها راه انتقال معنا نباشد؛ انیمیشن reduced-motion را رعایت کند.
- تست دستی با صفحه‌کلید و screen reader در فارسی و انگلیسی، از جمله dialog، انتخاب تنوع و checkout.

## امنیت و حریم خصوصی

- مجوز سروری و جلوگیری از IDOR در همه منابع خصوصی؛ تست کاربر A روی اطلاعات کاربر B و دسترسی کاربر عادی به پنل.
- validation، محدودیت حجم درخواست و upload، نوع واقعی فایل، نام امن، کنترل SVG و عدم اجرای فایل کاربر.
- CSRF، XSS، injection، SSRF و open redirect متناسب با معماری کنترل شوند؛ HTML محتوا sanitize شود.
- کوکی امن، TLS، security headers و CSP متناسب با درگاه و سرویس‌های واقعی؛ CSP صرفاً برای سبز شدن ابزار تضعیف نشود.
- rate limit ورود، OTP، بازیابی، AI و عملیات پرهزینه؛ در چند instance محدودیت به حافظه یک process وابسته نباشد.
- secrets در repo یا مرورگر نباشند؛ کلیدهای دارای دسترسی حداقلی، امکان rotation و لاگ پالایش‌شده.
- بررسی وابستگی‌ها و فایل lock؛ باگ‌های بحرانی پیش از انتشار رفع شوند.
- حداقل‌سازی داده شخصی، دسترسی محدود به اطلاعات سفارش و سیاست نگهداری/حذف مشخص؛ متن حقوقی با مالک و الزامات روز تطبیق داده شود.
- بکاپ خودکار و آزمون بازیابی؛ RPO/RTO پیش از انتشار با بودجه زیرساخت تعیین شوند.

## آزمون‌های ضروری

| سطح | سناریوهای اصلی |
| --- | --- |
| واحد | تبدیل ریال/تومان، محاسبه قیمت و تخفیف، validation ویژگی و transition سفارش |
| یکپارچه | خرید هم‌زمان آخرین کالا، رزرو/انقضا، callback تکراری و دیررس، تراکنش و rollback، مجوز منابع |
| مرورگر | ورود، انتخاب variant، افزودن به سبد، آدرس، پرداخت آزمایشی و نمایش نتیجه؛ در fa و en |
| چندزبانگی | برابری کلید پیام، ICU، locale نامعتبر، switch زبان، RTL/LTR و نبود overflow |
| AI | ابزار غیرمجاز، prompt injection، افشای سفارش دیگران، انقضای تأیید، سقف مصرف و قطع provider |
| دستی | موبایل واقعی یا نماینده، صفحه‌کلید، screen reader، تم‌ها و مرورگرهای هدف |

CI شامل بررسی تنظیمات مرکزی و ترجمه، lint، typecheck، تست‌های ضروری و build تولید است. تست پرداخت واقعی با محیط تست provider و سپس smoke کنترل‌شده طبق امکانات سرویس انجام می‌شود؛ mock تأیید اتصال واقعی نیست.

## Definition of Done

قابلیت در هر دو زبان و جهت، تم روشن و تاریک، حالت بارگیری/خطا/خالی، مجوزهای سرور و تست متناسب آماده است؛ مستندات و migration همگام‌اند. پیش از انتشار، مسیر خرید end-to-end، اطلاعات واقعی فروشنده، سرویس‌های تولید، بکاپ قابل بازیابی و گزارش کیفیت بررسی شوند. هیچ معیار اندازه‌گیری‌نشده به‌عنوان پاس‌شده گزارش نمی‌شود.
