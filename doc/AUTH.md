# احراز هویت و دسترسی

وضعیت R04: ورود اجرایی محلی و تست تکمیل شده؛ اتصال ایمیل واقعی OI-14 باز است. Better Auth 1.7.14 با adapter تراکنشی Prisma، PostgreSQL و Nodemailer 10.3.1 اجرا می‌شود. Gmail صرفاً آدرس حساب است؛ OAuth و OTP فعال نیستند.

## چرخه حساب

ثبت‌نام، ارسال دوباره تأیید، تأیید، ورود/خروج، بازیابی رمز، ویرایش نام، تغییر رمز و ابطال نشست‌های دیگر در فارسی و انگلیسی اجرایی‌اند. ایمیل normalize می‌شود؛ رمز ۱۲ تا ۱۲۸ کاراکتر با هش استاندارد کتابخانه ذخیره می‌شود. paste و password manager پشتیبانی می‌شوند. ثبت‌نام فقط CUSTOMER می‌سازد؛ نقش ارسالی مرورگر پذیرفته نمی‌شود. ورود قبل از تأیید ایمیل ممنوع است.

لینک تأیید یک ساعت و بازیابی نیم ساعت اعتبار دارد. identifier دیتابیس SHA-256 هدف و توکن است؛ value شناسه کاربر است، نه توکن خام. تأیید با مصرف اتمیک ledger و اعتبارسنجی امضای کتابخانه یک‌بارمصرف است؛ بازیابی از مصرف اتمیک کتابخانه استفاده می‌کند. لینک مرورگر توکن را در fragment می‌گیرد، فوراً از نوار آدرس پاک می‌کند و فقط با POST می‌فرستد. لینک منقضی یا مصرف‌شده رد می‌شود. تغییر و بازیابی رمز نشست‌های لازم را باطل می‌کند.

## نشست و مجوز

نشست دیتابیس انقضای مطلق ۲۴ ساعت دارد و refresh غیرفعال است؛ idle timeout جداگانه نداریم. کوکی HttpOnly، SameSite=Lax و در HTTPS برابر Secure است. کش کوکی نشست غیرفعال است. نقش، غیرفعال‌بودن و تأیید ایمیل در هر دسترسی خصوصی از دیتابیس بازخوانی می‌شود. API خصوصی no-store است و خروج یا تغییر هویت کش خصوصی TanStack Query را پاک می‌کند.

CUSTOMER فقط داده حساب خود را می‌بیند. ADMIN مجوزهای تعریف‌شده مدیریتی به‌جز مدیریت نقش‌ها دارد؛ OWNER همه مجوزهای تعریف‌شده را دارد. این mapping به معنی ساخته‌شدن API تجاری یا مدیریت نقش نیست. صفحه /admin فعلاً پوسته محافظت‌شده است؛ مدیریت کاتالوگ در R05 ساخته می‌شود. مجوز و مالکیت نشست در سرور بررسی می‌شوند.

نوشتن فقط با Origin دقیق برنامه، JSON و حداکثر ۸ KiB مجاز است. مسیرهای کتابخانه allowlist شده‌اند؛ callback خارجی، OAuth و endpoint نامربوط در دسترس نیستند. rate limit پایدار PostgreSQL شامل محدودیت مسیر و ۶ تلاش در دقیقه برای ایمیل نرمال‌شده است. X-Forwarded-For مورد اعتماد نیست؛ استقرار پشت proxy به تصمیم صریح trust نیاز دارد. پاسخ بازیابی و ارسال مجدد عمومی است. خطاها فاقد رمز، توکن و جزئیات داخلی‌اند.

## ایمیل و حساب مالک

AUTH_EMAIL_TRANSPORT=local فقط در local/test مجاز است: پیام در .tools/mailbox یا .tools/mailbox-test ذخیره می‌شود و به Gmail ارسال نمی‌شود. production/preview با auth فعال، SMTP دارای credential و APP_ORIGIN مبتنی بر HTTPS لازم دارند. ارسال واقعی، دامنه فرستنده و تحویل ایمیل هنوز بررسی نشده‌اند؛ R04 تا آن زمان DONE نیست.

ایمیل اعلام‌شده مالک فقط در env محلی ثبت شده است. فرمان pnpm auth:owner حساب را خارج از ثبت‌نام عمومی bootstrap می‌کند؛ اجرای مجدد رمز را reset نمی‌کند. ایجاد حساب جدید از این مسیر فقط local مجاز است؛ در تولید فقط حساب ازقبلتأییدشده قابل ارتقاست. رمز تصادفی اولیه در فایل .tools/owner-credentials.json نادیده‌گرفته‌شده توسط Git است. مالک باید لینک محلی را تأیید کند، وارد شود و رمز را تغییر دهد؛ تا تغییر رمز دسترسی مدیر بسته است. پس از استفاده فایل credential و پیام‌های محلی حذف شوند. رمز را در چت، مخزن یا Markdown قرار ندهید.

OTP، ادغام حساب، تغییر ایمیل و عملیات حساس به قرارداد جداگانه نیاز دارند. ویرایش فعلی پروفایل فقط نام را می‌پذیرد.

## تصمیم مالک — ۲۰۲۶/۱۰/۳۱

اتصال ایمیل واقعی به درخواست صریح مالک به بعد موکول شد. R04 با دامنه auth محلی و تست تکمیل و ادامه R05 مجاز شد؛ OI-14 و اتصال SMTP واقعی gate انتشار R11 باقی‌اند. اعتبارسنجی تولید و الزام HTTPS/SMTP بدون تغییر باقی می‌مانند.
