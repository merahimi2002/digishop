# دستورالعمل توسعه پروژه

## هدف و منابع

پیش از تغییر محصول، `BUSINESS_CONFIG.md`، `ROADMAP.md`، `EXECUTION.md` و سند تخصصی مرتبط را بخوانید. فهرست مرجع در README است. تصمیم‌های جدید کاربر بر مستندات قبلی اولویت دارند؛ مستندات را با تصمیم جدید همگام کنید.

مالک اجرای محلی R01 با آخرین نسخه‌های پایدار را مجاز کرده است. لوگوی DS/سبد و پالت سرمه‌ای/سبز تأیید شده‌اند. دامنه فعلی پایه پروژه است؛ سرویس تجاری و انتشار در این مرحله نیستند. دستیار مسئول طراحی، محتوا، تصاویر و پیاده‌سازی است؛ مالک بازخورد می‌دهد. برای انتخاب‌های معمول و برگشت‌پذیر پیش بروید و اطلاعات واقعی کسب‌وکار را جعل نکنید.

## اصول پیاده‌سازی

- TypeScript strict؛ از `any` و خاموش کردن بررسی‌ها بدون دلیل مستند پرهیز کنید.
- Next.js App Router، Server Components به‌صورت پیش‌فرض؛ مرز کلاینت را کوچک نگه دارید.
- TanStack Query برای داده تعاملی کلاینت؛ داده سروری را بی‌دلیل دوباره fetch نکنید. کش خصوصی کاربران و QueryClient سمت سرور نباید مشترک باشد.
- next-intl از ابتدا؛ متن UI در فایل پیام زبان، هویت برند از تنظیمات مرکزی. فارسی RTL و انگلیسی LTR را با هم بررسی کنید.
- Tailwind و shadcn/ui؛ CSS منطقی مانند inline/start/end. هیچ UI ضروری فقط با hover در دسترس نباشد.
- منطق تجاری در سرویس‌های مستقل از صفحه، Route Handler، Server Action و ابزار AI باشد.
- ورودی‌ها با Zod در سرور اعتبارسنجی شوند. مجوز هر عملیات و مالکیت منابع در سرور بررسی شود.
- مبلغ و موجودی از سرور؛ هیچ قیمت یا دسترسی ارسالی مرورگر قابل اعتماد نیست.
- secrets هرگز در bundle کلاینت، Markdown، خروجی ابزار، URL یا لاگ قرار نگیرند.
- وضعیت دمو، قیمت و محتوای آزمایشی روشن باشد؛ ادعای گارانتی، نماد اعتماد، نظر مشتری یا مشخصات محصول جعل نشود.
- تغییرات هویتی فقط در `BUSINESS_CONFIG.md`؛ تنظیمات تولیدشده را دستی تغییر ندهید.
- نسخه‌ها را هنگام نصب با مستندات رسمی تطبیق دهید؛ نصب بدون pin و lockfile قابل بازتولید نباشد.

## کیفیت و گزارش

وضعیت taskها مطابق state machine در ROADMAP و evidence در EXECUTION ثبت شوند. DONE فقط پس از شرط پایان واقعی؛ نوشتن endpoint یا دستور به معنی اجرای آن نیست. اطلاعات مالک با شناسه OI در OWNER_INPUT پیگیری و مقدار برند فقط در BUSINESS_CONFIG تغییر کند. پس از اتمام task، آمادگی وابستگی task بعد بررسی شود.

معیارهای `QUALITY.md` بخشی از تحویل‌اند. تست متناسب با ریسک بنویسید؛ منطق مالی و مجوزها تست معنادار می‌خواهند. تغییر کم‌ریسک محتوا نیازمند تست تقلیدی نیست.

پس از هر مرحله، نتیجه، بررسی‌های انجام‌شده و محدودیت واقعی را گزارش کنید. به‌دلیل موفقیت build ادعای تأیید performance، امنیت یا دسترس‌پذیری نکنید. پیش از انتشار واقعی، داده کسب‌وکار و سرویس‌ها باید آماده و انتشار مجاز باشد.


همه مستندات در doc هستند. سیاست نسخه‌ها در TECH_STACK: آخرین stable رسمی هنگام نصب، بررسی سازگاری و بدون downgrade خاموش. کامپایلر TypeScript 7 با alias رسمی کنار API سازگاری TS6 نصب است؛ lint با Oxlint. راهنمای ابزار محلی ویندوز در DEVELOPMENT است.
